# Agentic Multi-Hop RAG — case study frontend

A static, text-first Next.js case study for the project one level up in this
repository. Reads the project's already-committed `results/*.json`
artifacts directly at build time (`lib/data.ts`) and renders them as one
long-form page — no backend, no database, no live model calls.

## Develop

```bash
npm install
npm run dev
```

Requires the sibling `../results/*.json` and `../data/processed/*.json`
artifacts to already exist (they're generated by the Python pipeline
documented in the project root `README.md`) — this app only ever reads
them, never writes to them or calls a model itself.

The one interactive section (`Live Agentic RAG Demo`) calls a separate
FastAPI backend (`../backend/`, see its own docstring) at
`NEXT_PUBLIC_DEMO_API_URL` (defaults to `http://localhost:8000`). That
backend — not this frontend — holds the Mantle API key; nothing secret is
ever read by, or bundled into, this app.

## Build

```bash
npm run build
npm run start
```

The page is fully static (`○ (Static) prerendered as static content`) —
every number is read from disk once, at build time.

## Structure

- `lib/data.ts` — the only place that touches the filesystem; every
  `getX()` function reads one real result artifact.
- `lib/format.ts` — every number shown on the page is formatted here, never
  hand-typed inline in a component.
- `components/ui/` — reusable primitives (`Section`, `DataTable`,
  `MetricStat`, `BarChart`, `FlowDiagram`, `ChartPair`, `TableOfContents`).
- `components/sections/` — one component per case-study section, composed
  in `app/page.tsx`.
